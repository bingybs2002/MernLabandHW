# LLMs, Prompts & SDK

### 1. What is a system prompt and how is it different from a normal prompt?

A system prompt is the developer-controlled instruction set given to the model before the conversation, defining its role, behavior, tone, rules, output format, and available context, such as "You are a support assistant for Acme; answer only from the provided docs and reply in JSON." It applies to every turn and has higher priority. A normal (user) prompt is the individual message or question the end user sends in each turn. In an API call, the system prompt goes in the system parameter while user prompts go in the messages array; the app sets the system prompt, users supply the user prompts.

### 2. Explain the common prompting techniques

Prompting techniques control how much guidance and how many examples the model gets, and whether it reasons step by step before answering.

- **zero-shot**  
  Asking the model to do a task with instructions only, no examples: "Classify this review as positive or negative." It works well for simple, common tasks that modern models already understand.
- **one-shot**  
  Giving exactly one example of the input and desired output before the real input, which shows the expected format or style.
- **few-shot prompting**  
  Giving several (typically 2-5) diverse input-output examples so the model learns the pattern, labels, tone, and format. It improves consistency on tasks with specific formats or edge cases; examples should be varied and representative.
- **chain-of-thought**  
  Asking the model to reason step by step before giving the final answer ("think through this step by step"), or showing worked reasoning in examples. It improves accuracy on math, logic, and multi-step problems at the cost of more tokens; many current models have built-in extended thinking that does this automatically.

### 3. What is structured output, why do we need it, and how do you do it?

Structured output means getting the model's response in a predictable machine-readable format, usually JSON that matches a schema, instead of free text. We need it when code consumes the result: filling a database, calling functions, rendering UI, or chaining steps, because free text is hard to parse reliably. How: describe the format with examples in the prompt; better, use the provider's structured-output or JSON-schema mode or tool calling, which constrains the output to the schema; define the schema with Zod or Pydantic (for example the Vercel AI SDK's generateObject or LangChain's withStructuredOutput); then always validate the result in code and retry or fall back on failure.

### 4. What is AI's hallucination? How do we reduce it?

Hallucination is when a model generates content that sounds confident and plausible but is false or unsupported, such as made-up facts, citations, APIs, or package names, because it predicts likely text rather than looking up truth. Reduce it by grounding answers in retrieved sources (RAG) and instructing the model to answer only from the provided context and say "I don't know" otherwise; asking for citations or quotes from the source; giving clear, specific prompts with enough context; using tools for facts and calculations (search, database, calculator); lowering temperature for factual tasks; validating outputs with schemas, tests, or a second checking step; and keeping a human in the loop for high-stakes outputs.
